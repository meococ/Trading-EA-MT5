## 1. Verdict in one page

### The single most important structural problem

**The gates verify provenance with real rigor and verify decisions not at all.** Every hash, byte count, path-containment check, directory-tree closure and run-identity binding in this repo is strict and works. But at the exact point where a number decides something — trades, PF, non-repaint status, minimum observations, "frozen before outcome" — the value is *typed by the audited party into a contract object*, and the artifact that could contradict it is hash-bound and never opened. Two seats proved this independently by execution: `validate_ea_delivery_packet.py` emits `EA_DELIVERY_PACKET_OK ... verdict=CONFIRMED` on a packet whose bound non-repaint audit reads `{"status":"FAIL"}`, whose bound lifecycle CSV has zero trade rows against a declared 40, and whose bound `run_manifest` says `model:1`; `validate_fast_kill_closeout.py` emits `FAST_KILL_CLOSEOUT_OK ... verdict=KILLED` on one trade whose bound compile log reads `Result: 17 errors, 4 warnings`. I confirmed the mechanism statically: the role names `nonrepaint_audit`, `test_receipt`, `run_manifest`, `lifecycle_trades` occur in `02. AlphaFactory/tools/validate_ea_delivery_packet.py` **only** inside `BASE_BINDINGS` (lines 26-30) and are never passed to a reader.

The same shape recurs everywhere the seats looked, which is why it is structural and not a bug list: `promotion_eligible` is a hardcoded literal in all four promotion producers (`cscv_pbo.py:199`, `white_reality_check.py:138`, `walk_forward.py:75`, `robustness_suite.py:63`); the registry's `validation` object is `{"type": "object"}` (`CANDIDATE_REGISTRY.schema.json:73`) so 455 path/SHA pairs ride unchecked; `frozen_pre_outcome` is `payload.get(key) is not True` (`aligned_variant_evidence.py:123`) with no timestamp anywhere; the spread-coverage predicate is `bid > 0 and ask >= bid` (`build_verified_cost_artifact.py:202`), which counts a zero-spread row as valid cost coverage. The fix class is uniform and cheap: **make each validator read the artifact it already binds.** The fix class is *not* new documents or new rules.

## 3. Gate integrity: what the gates actually enforce

Nine fail-open paths and unenforced rules, each with the bypass in one sentence and the fix.

1. **Delivery gate never reads six of the artifacts it binds** (`gates-01`, `tests-01`). *Bypass:* type `nonrepaint_status: "PASS"`, `trades: 40`, `tests_passed: 12` into the contract; bind the real FAIL audit, an empty CSV and a `{"passed":0,"failed":99}` receipt with correct hashes; the gate compares the contract to itself and prints OK. *Fix:* add a `validate_artifact_agreement` step in `02. AlphaFactory/tools/validate_ea_delivery_packet.py` — the reconciliation is already written elsewhere in the repo as `_nonrepaint_audit_evidence` (`unified_validation.py:1260-1330`), so call that shape rather than writing new logic. Note real packets store 2 CSV data rows per trade (OPEN+CLOSE), so a naive `rows == trades` check would false-fail every one.
2. **Delivery `verdict` is uncoupled from any validation evidence.** *Bypass:* `VERDICTS` admits `"CONFIRMED"` (`:17`) and the OK receipt prints it (`:564`), but `BASE_BINDINGS` contains no `validation_summary`, no `verified_execution_cost` and no cost/WFA/PBO/WRC role — so `verdict=CONFIRMED` can be emitted for a run on which `validate-full` was never invoked. *Fix:* require a `validation_summary` binding and require its `stage`/`verdict` to support the packet's verdict word.
3. **Neither packet validator enforces the archive-source Hard Invalidation.** *Bypass:* `validation_gates.md:220` makes compiling from `00. ## 4. Statistical & inference validity

**Confirmed defects in the promotion-tier statistics.** All are on a tier no candidate has reached, which is why severities were deflated from the seats' "critical" — but they are the tier that would authorize capital.

- **PBO is unproducible at the mandated window and a coin flip at the schema floor.** `cscv_pbo.py:85-86` materialises an intermediate `timedelta` of `span_seconds²`, overflowing above 107.58 days (my reproduction: 107 OK, 108 fails, 2557 fails). At `cscv_max_combinations: 1` (schema-legal, `minimum: 1`) two pure-noise variants pass `PBO < 0.20` in 50.75% of seeds, and two byte-identical variants give `PBO = 0.0` deterministically because `max()` and the stable descending sort both favour the first-inserted key. At the shipped template default of 200 combinations a noise pair passes only 18.5% of the time, so the coin-flip result is a floor property, not the default. Separately, `cscv_pbo.py:149-150` averages per-slice ratio metrics instead of computing the statistic on the concatenated IS/OOS submatrices, and the default `sharpe` metric multiplies each slice by `sqrt(n)` (`:58`) — I confirmed by execution that two variants with *identical* per-trade edge but 3× cadence yield `PBO = 0.029`, i.e. the ranking selects on trade count.
- **White Reality Check applies zero data-snooping correction at the shipped template config.** `differentials` excludes the baseline, so `expected_variant_ids: ["baseline","variant_a"]` (`ALIGNED_VARIANT_MANIFEST.template.json:12`) yields one differential and `max(...)` at `:132` is a maximum over a singleton. - **The robustness gate reduces to "both arms had a positive mean", with the baseline scored as one of its own robustness variants.** `robustness_suite.py:55` is the entire test (`mean_net_r >= evidence.minimum_variant_mean_net_r`), the template sets that threshold to `0.0` and lists `["baseline","variant_a"]`, and the schema puts no lower bound on it (`:35`) — the repo's own test already exercises a *negative* threshold (`test_promotion_producers.py:105`, `-0.01`). ### Is the GOAL spec jointly feasible as written? — the arithmetic

The spec (`01. GOAL/GOAL.md:107-113`): PF > 1.30 after verified real cost **AND** 2-5 trades/week per split by elapsed calendar weeks **AND** x1.5 PF ≥ 1.25 **AND** x2 PF ≥ 1.00 **AND** 84 months / 14 half-years / 7 years **AND** train and holdout each passing independently.

**(a) The PF-vs-cost arithmetic demands a win rate the repo has never approached.** Required win rate at fixed R is `reqW(T,b,k) = T(1+k) / ((b−k) + T(1+k))` where T is target PF, b realized payoff in R, k cost in R. I validated the formula against the workspace's own number: at b=1.0586, k=0, T=1.0 it returns 48.58%, exactly `hot.md:134`. At the repo's typical geometry — 8-pip stop, realized payoff 1.0586R (VRAS-008 measured: nominal 1.5R compresses to 1.0586R), 1.5-pip cost = 0.1875R:

| Gate | Cost in R | Required WR |
|---|---|---|
| x1: PF > 1.30 | 0.1875 | **63.9%** |
| x1.5: PF ≥ 1.25 | 0.28125 | **67.3%** |
| x2: PF ≥ 1.00 | 0.375 | **66.8%** |

The highest win rate ever measured anywhere in this repo is **47.151%** (`hot.md:195`, HYP-017, N=3,703 fully reconciled tester trades, PF 0.7553). The gap is 16.7-20.2 percentage points. No achievable improvement in entry selectivity closes that.

**(b) The same arithmetic says the binding axis is payoff, not entry — and the project has searched the other one.** Hold WR at the measured 47.15% and raise realized payoff from 1.0586R to 2.0R at the same 8-pip stop: required WR falls to 46.0% (x1), 48.2% (x1.5), 45.8% (x2). The binding gate becomes x1.5 at 48.2% — about **1 point** short instead of 20. Yet 45 of 84 IDs searched ICT/SMC entry variants and only 3 of 84 ever varied exit/payoff geometry. The 1.5-pip cost is 18.75% of an 8-pip R, which is why the cost-to-stop ratio dominates: widening the stop or extending the payoff both attack it; a better entry does not.

**(c) The cadence band is unreachable for multi-gate confluence on one symbol at one timeframe.** 2.0 tpw over the 208.714-week window = 417.4 trades. Measured gate-chain survival on EURUSD M5 2019-2022: SCC 3-stage 286/1242 = 23.02%; ECRS 5-gate 30/462 = 6.49%; ECRS 6-gate 8/462 = 1.73%. Required *raw* trigger rates are therefore 8.69/wk, 30.8/wk and 115.6/wk. Measured raw supply is 5.951/wk (SCC BREAK arms) and 2.213/wk (ECRS G1∧G2∧G3). **Shortfall 1.46× to 52×.** Three independent lanes converged on the same ceiling — 1.3703, 1.3415, 1.434 tpw — which is the fingerprint of the symbol/timeframe's event supply, not of the individual mechanisms.

**(d) "84 months of verified real cost" has no acquisition path shorter than the window.** The verified-cost corpus that exists is 894,192 same-broker XAU M1 spread observations covering 2024-01-02 → 2026-07-15 — about 30.4 of the required 84 months (36%), wrong symbol, with zero commission lifecycles and zero slippage fills. For EURUSD, 24.555% of the broker's M1 spread rows are zero (I re-derived: 366,196 / 1,491,312 for 2019-2022; 38.61% across the whole M1 series; **93.25% / 93.93% / 95.28% / 94.71%** for 2023/24/25/26 — the broker's cost column is effectively dead in the recent era). `validation_gates.md:230-231` forbids synthesizing promotion-grade ask barriers from bar-level spread when chronological bid/ask ticks are unavailable. Forward tick collection accrues at real time, so filling an 84-month verified-cost window that way has a ~7-year lead time. One partial mitigation the seat missed: `validation_gates.md:244` already accepts a hash-bound JSON broker contract for the commission component, implemented at `build_verified_cost_artifact.py:629-638` — so the unfilled hole is specifically **historical chronological bid/ask and slippage**, not commission.

### The honest read

**As written, the five conditions are not jointly satisfiable by the mechanism class and data shelf currently in scope.** Each condition is individually defensible. Two of them are not jointly satisfiable with the search actually being run: the 2-5 tpw band cannot be met by a ≥3-gate confluence mechanism on one symbol at one timeframe (1.46×-52× short, measured three times), and the 84-month verified-cost requirement cannot be met by any corpus obtainable faster than the window it must fill. And the PF-plus-cost-stress conjunction demands a 64-67% win rate at the payoff geometry every lane has actually produced, against a measured ceiling of 47.15%. **Yes — the goal spec is what kills candidates before economics is ever measured.** Five Stage-0 parks and 13 of 16 out-of-band economic reads are the direct evidence: those lanes were closed on a cadence floor, not on a measured absence of edge.

That is not a reason to stop. It is a scope decision, and it is the Owner's, not mine. Four options with honest tradeoffs:

| Option | What changes | Buys | Costs |
|---|---|---|---|
| **A. Change the search axis, not the spec** | Open an exit/payoff-geometry mechanism family (partial at +0.5R, structural trailing, MFE-conditional targets) as the next class instead of another entry variant | The only axis with arithmetic headroom: b=1.06R→2.0R moves the required WR from 63.9% to 46.0%, inside measured reach | Abandons the ICT/SMC entry thesis 45 IDs are invested in; no guarantee payoff extension survives cost |
| **B. Pre-declared multi-symbol/TF grid inside one prereg** | One `hypothesis_id` owns N cells; `cells[]` frozen pre-outcome in the schema | Raw structural event supply scales roughly linearly with symbol count — the only lever that can close a 1.46× shortfall | Requires acquiring same-broker M1 for 7+ majors (the real cost, not the ~24 tester-minutes); honest trial-budget inflation, charged at ~+45% required Sharpe going 20→200 cells |
| **C. Two-tier cost contract** | Conservative *reconstructed* historical cost (declared upper bound on the zero-spread rows + published per-lot commission as a bound contract) for research-pass and confirmed; same-broker *verified forward* cost required only for deploy, over a declared 6-12 month forward window | Unblocks the only gate with a 7-year lead time, without weakening the deploy bar | Confirmed-stage PF becomes a bound rather than a measurement; must be written down explicitly or it is threshold-softening |
| **D. Relax the cadence band with a stated reason** | e.g. 1.0-5.0 tpw for confirmed, keeping 2-5 for deploy sizing | Immediately admits the three mechanisms measured at 1.34-1.43 tpw to an economic read they never got | Fewer trades means wider confidence intervals on every statistic and less capital efficiency; must not be done to rescue an already-dead lane (that is post-hoc rescue per `research_doctrine.md:90-103`) |

My recommendation, with the reasoning shown: **A + C now, B when the data budget is approved, D last.** A costs nothing but a choice of next mechanism and attacks the axis the arithmetic identifies. C is the only fix for a blocker whose lead time exceeds the project. B is the only fix for cadence but its true cost is data acquisition, not tooling. D I would defer because it changes a GOAL number to admit lanes that are already terminal, which is the shape of a rescue even when done honestly — and if A raises realized payoff, the cadence math changes anyway (fewer, larger trades is a different point on the same surface).

**What the arithmetic does not say:** it does not say no edge exists on EURUSD M5. It says the *conjunction as written* prices out the mechanism class being searched. Zero of 16 economic reads were positive, which is real evidence against those 16 specific objects and no evidence at all about the ~68 IDs that never got a read.
